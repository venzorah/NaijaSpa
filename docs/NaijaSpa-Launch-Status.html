3. Supabase PostgreSQL setup

The website stays on Vercel. Supabase is the database only. Keep NaijaSpa login, Google, and Paystack as they are.

Create the project

  1. Open supabase.com → New project. Pick a region close to West Africa if you can, otherwise EU.
  2. Save the database password. You will not see it again.
  3. Wait until the project is healthy. Then Connect → ORMs → Prisma.

Two URLs

Variable Which URI
DATABASE_URL Transaction pooler, port 6543. Add ?pgbouncer=true&connection_limit=1
DIRECT_URL Session pooler or direct, port 5432 (needed for prisma migrate) 
DATABASE_URL="postgresql://postgres.xxxx:PASSWORD@aws-0-REGION.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1"
DIRECT_URL="postgresql://postgres.xxxx:PASSWORD@aws-0-REGION.pooler.supabase.com:5432/postgres"

URL-encode special characters in the password. If the direct db.xxxx.supabase.co host fails from Windows, use the session pooler on port 5432 as DIRECT_URL.

Put this on Vercel

Variable Value
DATABASE_URL Transaction pooler
DIRECT_URL Session / direct
AUTH_SECRET Long random string (not the example in .env.example)
APP_URL https://naijaspa.com
PAYSTACK_SECRET_KEY / public key Test keys first, live later
USE_DEMO_LISTINGS Leave unset

Redeploy after saving. Never put the Supabase anon or service_role key in the browser.

Apply the schema (from your PC)

$env:DATABASE_URL="postgresql://…:6543/postgres?pgbouncer=true&connection_limit=1"
$env:DIRECT_URL="postgresql://…:5432/postgres"
npx prisma migrate deploy

Do not run npx tsx prisma/seed.ts on production. That seed uses the public demo password. Create a real admin after migrate.

Check it worked

npx prisma migrate status

Open https://naijaspa.com/login. If you still see Osun / Olive / Maitama Hands and cannot log in, Vercel has no live DATABASE_URL.

Paystack webhook stays on the app: https://naijaspa.com/api/payments/webhook

Backups

Turn on daily backups in the Supabase dashboard (Pro). On the free tier, take a manual dump before go-live. Do not edit tables in the SQL editor — Prisma owns the schema.

6. You may call it launched when

  • naijaspa.com serves this app from Vercel over HTTPS
  • Supabase Postgres is live, Vercel can reach it, and the demo catalog is off
  • A new customer can register, search a state, book, pay Paystack, and see confirmed
  • The vendor sees the booking and a pending earning
  • Admin sees the payment as success
  • Privacy and terms are real documents
  • Backups exist and the Paystack webhook is green on a live charge.success

Until every box is true, NaijaSpa is a preview.

7. Launch-week order of work

  1. Create the Supabase project and copy pooler + direct URIs (section 3).
  2. Set Vercel env: DATABASE_URL, DIRECT_URL, AUTH_SECRET, Paystack keys, APP_URL=https://naijaspa.com.
  3. From this PC: prisma migrate deploy. Do not seed demo people.
  4. Staging: Paystack test charge against a preview deployment.
  5. Admin: plan prices, commission, gallery limits.
  6. Invite 1–3 real vendors; they add services and photos (durable object storage, not Vercel disk).
  7. You book and pay a real ₦ amount; confirm booking and earning.
  8. Point naijaspa.com at Vercel. Watch webhook 200s and Vercel logs for 24 hours. Confirm Supabase backups.
